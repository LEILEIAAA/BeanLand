# 计划：预约拒绝原因字段

## 目标

店主拒绝预约时必填拒绝原因（快捷推荐 + 手输），持久化到预约记录；店主预约管理与会员「我的预约」均展示该原因。

## 范围

- 含：`rejectReason` 校验与写入、`adminUpdateAppointment` reject 入参、店主拒绝面板、两端列表展示
- 不含：订阅消息推送、历史已拒绝记录回填

## 现状

- 店主拒绝仅 `wx.showModal` 确认，云函数只写 `status/rejectedAt`
- 会员端仅展示状态文案「已拒绝」

## 改动方案

1. `appointmentRegistration` 增加快捷常量、`assertRejectReason` / `buildRejectFields`
2. 云函数 `handleReject` 校验并写入 `rejectReason`
3. 店主端底部面板：快捷芯片填充输入框，支持手改，空原因不可提交
4. 店主列表 / 会员「我的预约」展示 `rejectReason`

快捷原因：`时段已满` / `人数超限` / `临时闭店` / `其他`（不含「信息不完整」）

## 风险

- 需同步更新云函数本地 `appointmentRegistration.js` 副本
- 拒绝面板为新 UI，需确认在小程序内可滚动与安全区

## 验证思路

- `node --test tests/appointmentRegistration.test.js`
- 静态检查：页面含拒绝原因面板与会员展示字段
