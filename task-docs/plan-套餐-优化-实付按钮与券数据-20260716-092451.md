# plan-套餐-优化-实付按钮与券数据

**执行状态：** done

**Nova run：** 20260716-092325  
**需求确认：** 实付区双按钮简化；核查优惠券是否真实拉数、可用性逻辑是否存在

## 目标

1. 实付区操作按钮简化为单一确认 CTA（取消靠点遮罩关闭）
2. 套餐购买优惠券改为读取 `user_coupons`（`listMyCoupons`），可用性判断对齐云券模型

## 现状（核查结论）

- 可用性逻辑存在于 `packagePurchase.js`（`isCouponAvailable` / `isCouponApplicable` / `scopeMatchesPackage`）
- 套餐页与支付云函数读的是 `member.coupons`；真源已迁到 `user_coupons`（会员专页走 `listMyCoupons`）
- 状态词不一致：购买逻辑认 `available`，云券是 `unused` + `available` 布尔
- 云券权益是 `hours`/`discount`，购买逻辑认 `amount` 面额；小时券不应进套餐抵扣

## 范围

- In：套餐弹层 UI；`packagePurchase` 适配云券；前端拉 `listMyCoupons`；购买/下单/回调改写 `user_coupons`
- Out：发券规则变更；小时券抵套餐价；改优惠券专页

## 改动方案

- UI：去掉「取消」，保留单主按钮；实付字号收一收
- 纯函数：识别 `unused`、折算折扣券抵扣额、排除小时券；导出规范化入口供页面使用
- 云函数：按 couponId 读/hold/used `user_coupons`，不再写 `members.coupons`

## 风险

- 历史若仍把券写在 `members.coupons`，购买侧将不再识别（按零兜底直接切真源）
- 无 `amount` 的折扣券依赖 `benefitValue` 折算，需单测锁死
