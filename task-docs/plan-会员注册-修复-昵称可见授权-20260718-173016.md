# 计划：注册页微信昵称可见授权

## 目标
修复注册页「选用微信昵称」无法独立调起授权；须先走头像/手机号后才可用的问题。

## 范围
- `miniprogram/pages/member/register/index.wxml`
- `miniprogram/pages/member/register/index.wxss`

## 现状
昵称用 `opacity: 0` 的 `type="nickname"` 覆盖假按钮；设置页/首页引导用可见输入框。透明层在微信侧常不触发隐私授权与「使用微信昵称」。

## 改动方案
去掉透明覆盖层，改为可见 `type="nickname"` 输入框（未填黑底按钮态、已填弱链接态），对齐首页/设置页模式。逻辑 JS 不变。

## 风险
真机才完整验证「使用微信昵称」条；开发者工具可能仍只显示普通键盘。

## 验证思路
- 静态：wxml 无 `nickname-auth-hit` / 透明覆盖；存在可见 `type="nickname"`。
- 回归：`node --test tests/memberProfile.test.js tests/memberRegisterGate.test.js`
- 真机：冷启动进注册页，未选头像/手机号时点昵称应能弹出授权或键盘上方「使用微信昵称」。

## 执行状态
`done`（第二轮已落地，待真机确认）

## 根因修订（第二轮）
1. 注册页独有 `bindinput` + 拒打字并清空，会冲掉微信昵称填充；工作页（设置/首页/预约）只用 `bindblur`。
2. `__usePrivacyCheck__` 下昵称聚焦常不触发隐私同意；头像/手机号会触发——与「先走另外两项」现象吻合。需 `wx.requirePrivacyAuthorize`。
3. 圆角胶囊 + 无固定高度导致原生 input 裁切（显示不全）。
