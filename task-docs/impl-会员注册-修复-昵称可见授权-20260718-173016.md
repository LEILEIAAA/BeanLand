# impl-会员注册-修复-昵称可见授权

## 实际改动

### 第一轮
去掉 `opacity:0` 透明覆盖，改为可见 `type="nickname"`。

### 第二轮（真机仍失败后）
对齐设置页/首页/预约的可用模式，并补隐私预授权：

1. **去 `bindinput` / `nickDraft` 受控清空**  
   仅 `bindblur` 保存；避免逐字 input 清空冲掉微信昵称回填。
2. **`wx.requirePrivacyAuthorize`**  
   `onShow` + `onNicknameFocus` 主动拉起隐私同意（`__usePrivacyCheck__` 下昵称聚焦常不触发，头像/手机号会——与「先走另外两项」吻合）。
3. **样式**  
   固定高度 `88rpx`、矩形 `16rpx` 圆角、浅底左对齐，避免胶囊裁切导致「显示不全」。

## 关键决策

- 注册页昵称交互与首页引导一致：可见 input + blur 落库。
- 仍提示「点键盘上方使用微信昵称」；不再在 input 阶段做逐字拒收。

## 残留风险

- 昵称不是手机号那种授权弹窗，而是键盘上方「使用微信昵称」；需真机、且隐私指引已声明头像昵称。
- 进页若弹出隐私保护提示：先点「同意并继续」，再点昵称输入框，选键盘上方昵称后失焦保存。
- 开发者工具常无「使用微信昵称」条。

## 后续事项

真机按上述路径回归；若同意隐私后仍无昵称条，查公众平台隐私指引是否声明「微信昵称」。
