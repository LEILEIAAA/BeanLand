# 实现记录：一人一座 + 结伴批量开台 + 自动延时

> 对应规格：`docs/superpowers/specs/2026-07-16-seat-session-timer-design.md`  
> 对应计划：`docs/superpowers/plans/2026-07-16-seat-one-per-member-batch.md`  
> 时间：2026-07-16

## 实际改动

1. **纯函数** `miniprogram/utils/seatSession.js`
   - 新增 `assertCanStartSeatBatch` / `buildStartPairs` / `calcSessionTime` / `buildEndSessionFields`
   - 开台改为一人一座批量校验；去掉开台连座强制
   - 延时由现算 phase + 结束写入 `totalMinutes` / `overtimeMinutes`

2. **云函数**
   - `adminStartSeatSession`：`memberIds[]` + `seatIds[]` 按序配对整批开台（兼容旧 `memberId`）
   - `adminEndSeatSession`：整场结束并写累计字段；去掉部分结束路径
   - `adminListSeatBoard`：返回 `phase` / `overtimeMinutes` / `remainingMinutes`

3. **计时页**
   - 有序多选会员、有序多选座位、配对预览
   - 去掉 +15/+30 与部分结束
   - 过点展示「已延时 X 分钟」

## 验证

- `node --test tests/seatSession.test.js` → 6 pass

## 残留风险

- 批量开台非数据库事务：极端失败可能留下部分会话（当前为顺序写入；失败概率低）
- `adminExtendSeatSession` 仍部署在云端但 UI 已不再调用
- 需真机再验：结伴 2 人 2 座开台、过点展示、单人结束累计
