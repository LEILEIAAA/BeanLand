# impl-活动管理-修复-封面选图隐私失败

**对应计划：** `task-docs/plan-活动管理-修复-封面选图隐私失败-20260717-214256.md`

## 实际改动

- 新增 `miniprogram/utils/mediaPickError.js`：区分 cancel / 隐私未授权 / 隐私指引未声明照片 / 权限拒绝 / 选图失败 / 上传失败。
- `privacy-popup`：文案补「选中的照片（相册/相机）」；`detached` 时 `offNeedPrivacyAuthorization`，避免脏监听。
- 活动编辑封面：在点击同步栈内直接 `wx.chooseMedia({success/fail})`（不可先 await 隐私，否则丢手势）；上传拆到 `uploadChosenCover`；空态热区用 `button`；失败用 modal/toast 展示可行动原因（含原始 errMsg）。
- 首页轮播、我的拼豆：同源「同步 chooseMedia + 后置 upload」与错误映射。

## 关键决策

- 现象「一点就失败、相册未开」定位为 `chooseMedia` 前置失败（隐私），不是云上传。
- 可测逻辑抽到 `mediaPickError`；微信 API 胶水本身不做模拟器假测。

## 残留风险 / 后续

- 若 toast/modal 出现「隐私指引未声明照片」：需在微信公众平台 → 用户隐私保护指引中勾选「选中的照片或视频」，与提审清单 A4 一致；代码无法代替后台声明。
- 真机需再点一次封面确认：未同意时先出隐私弹窗，同意后出相册。
- **二次修正（同任务）：** 去掉点选前的 `await requirePrivacyAuthorize()`——该 await 会丢掉用户手势，导致 `chooseMedia` 一点击立刻 fail。改为在 tap 同步栈内直接 `wx.chooseMedia({ success/fail })`。
