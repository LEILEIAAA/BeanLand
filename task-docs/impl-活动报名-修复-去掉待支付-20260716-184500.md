# 活动报名去掉待支付 — 实现记录

## 实际改动
- 移除报名状态 `pending_pay` /「待支付」。
- 微信支付下单写入 `activity_pay_orders`（`paying`），支付成功回调后才写入 `activity_registrations`（`paid`）。
- 「我的活动报名」仅返回 `paid` / `refund_pending`。
- 报名页不再把待支付当作「已报名」；微信付款后轮询确认到账。

## 关键决策
- 支付过程态与用户可见报名记录拆开：用户侧只有「已购买 / 未购买」，无中间态展示。
- 支付中仍用 `activity_pay_orders.paying` 防重复下单，但不进入报名列表。

## 残留风险
- 云端需新建集合 `activity_pay_orders`（若环境尚无），并重新部署相关云函数。
- 历史 `activity_registrations` 中若有 `pending_pay`，用户列表已过滤；可择机清理或标记 failed。
- 支付回调延迟时，前端会提示「支付处理中」，需依赖 notify 最终落库。
