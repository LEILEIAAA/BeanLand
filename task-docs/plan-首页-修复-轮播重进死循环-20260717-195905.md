# 首页轮播重进死循环

## 目标
修复会员端首页 hero 轮播在离开再进入（Tab 重进 / onShow）后出现的无限循环抖动。

## 范围
- `miniprogram/pages/home/index.js` / `index.wxml`
- 抽出可测纯函数：`miniprogram/utils/homeHeroSwiper.js`
- 测试：`tests/homeHeroSwiper.test.js`

## 现状 / 根因
1. `swiper` 的 `current="{{heroIndex}}"` 与 `bindchange → setData({ heroIndex })` 形成双向回写。
2. `circular="{{true}}"` 下，对 `current` 的反复 setData 会持续触发 `change`，表现为无限循环。
3. `onShow` → `loadHeroPhotos` 每次强制 `heroIndex: 0`，重进时与 swiper 内部位置/自动播放冲突，放大死循环。

## 改动方案
1. 拆分展示态 `heroIndex` 与受控跳转 `swiperCurrent`：`change` 只更新展示态，不回写 `current`。
2. 圆点点击才写入 `swiperCurrent`。
3. 重载轮播数据时不强制重置到 0；仅在越界时钳位，且不主动改 `swiperCurrent`（避免打断/回写）。
4. 纯函数覆盖：change / dot / reload 三类 patch。

## 风险
- 圆点跳转依赖 `swiperCurrent` 变更；同索引重复点击需短路。
- 云端 banner 数量变少时需钳位 `heroIndex`，否则 caption 错位。

## 验证思路
- `node --test tests/homeHeroSwiper.test.js`
- 逻辑复核：change 返回的 patch 不含 `swiperCurrent`；reload 不含强制 `swiperCurrent: 0`。
