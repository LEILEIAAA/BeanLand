# 实现：停止计时后沉淀「本次记录」产物

## 实际改动
### 数据模型（seat_sessions）
- 开台新增字段：`packageOrderId`、`packageName`、`consumedAmount`（元）。
- 结束新增字段：`seatIdsSnapshot`（结束时 seatIds 被清空，用快照保留原座位）。

### 后端
- `utils/seatSession.js` + 5 份云函数副本同步：
  - `buildStartSessionRecord` 增消费字段。
  - `buildEndSessionFields` 增 `seatIdsSnapshot`。
- `adminStartSeatSession/index.js`：解析 `event.packageOrderId` → 读 `package_orders`（取 `payAmountYuan` / `packageName`）→ 挂到 memberId 匹配的会话（单会话则直接挂）。
- 新增 `adminListSeatSessions`（店主，status=ended，endedAt 倒序，可按 memberId 过滤，集合缺失容错返回空）。
- 新增 `listMySeatSessions`（会员，按 memberOpenid 查，内存按 startedAt 倒序，避免索引依赖）。

### 前端
- 新增 `utils/seatSessionHistory.js`：`formatDurationLabel` / `formatAmountLabel` / `mapAdminSessionRow` / `mapMemberSessionRow`，对旧数据（无 snapshot/amount）容错。
- `utils/api.js`：`adminListSeatSessions`、`listMySeatSessions`。
- `pages/admin/timer/index.js`：onLoad 解析 `packageOrderId`，startSession payload 带上，开台成功后清空。
- 新增 `pages/admin/timer-history/`（计时复盘列表，dashboard「计时复盘」入口）。
- 新增 `pages/member/seat-sessions/`（到店记录，会员页「到店记录」快捷入口）。
- `utils/memberActions.js` + `pages/member/index.js`：新增 `seatSessions` 入口与路由。
- `app.json`：注册两个新页。

## 关键决策
- 消费额来源锁定为「开台前核销的套餐 payAmountYuan」，符合用户「本次核销时记录该字段」的意图；一次会话仅记录开台绑定的那笔套餐。
- 结束不改动原 `seatIds:[]` 清空行为，改用快照字段，零回归风险。
- 会员端映射不暴露他人信息；店主端才带昵称/手机尾号。
