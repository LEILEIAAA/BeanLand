# 计划：会员设置页与用户协议/隐私政策入口

## 目标
- 新增独立「设置」页，把当前散落在会员卡/注册页的头像、昵称、手机号等资料管理收敛进去。
- 以列表行（list-row）交互样式新增「用户协议」「隐私政策」两个入口及对应内容页。
- 退款规则页（充值/套餐/活动）本轮不做，待确认。

## 范围
- 新增页面：`pages/member/settings/index`、`pages/legal/agreement/index`、`pages/legal/privacy/index`。
- 修改：`app.json`（注册页面）、`pages/member/index`（设置入口）。
- 注册页 `pages/member/register` 保留：仍作为充值/套餐/活动/预约下单前的"完善资料"前置门。

## 现状
- 头像/昵称/手机号编辑逻辑集中在 `pages/member/register/index.js`（chooseAvatar / nickname input / getPhoneNumber）。
- 会员页 `pages/member/index` 点头像 → 注册页。
- 会员数据模型无性别/生日/邮箱字段；有 `_id`/`id` 可作会员号展示。
- 全项目无用户协议/隐私政策页面。

## 改动方案
- 设置页复用注册页的头像/昵称/手机号云同步逻辑，列表行呈现：头像、昵称、会员号（只读）、手机号；再加「用户协议」「隐私政策」两行跳转。
- 会员页头像卡点击 → 设置页（设置页含手机号授权，是注册的超集）。
- 协议/隐私为静态内容页，文案为可用模板（含手机号收集说明），后续按主体信息替换。

## 风险
- 注册页与设置页并存，均可改资料；注册页仅在强制完善场景使用，设置页为日常入口，功能一致不冲突。
- 会员号以记录 id 展示，缺失时占位 `—`。

## 验证思路
- 页面路径全部登记进 app.json，无死链。
- 开发者工具编译无报错；ReadLints 无新增错误。
- 手动核对：会员页点头像进设置页、各行交互、协议页可打开。
