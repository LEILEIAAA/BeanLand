# plan-预约-修复-选座同步体验中状态

## 目标

预约管理确认选座时，同步座位管理的现场状态（体验中 / 维护），不可再选占用中座位。

## 执行状态

`done`

## 范围

- `miniprogram/utils/seats.js`：占用集合构建识别无 date/timeSlot 的现场占用
- `miniprogram/utils/api.js`：`getOccupancies` 额外拉取 in_use / maintenance
- `cloudfunctions/adminUpdateAppointment`：确认排座后端同样拦截
- 同步相关云函数 `seats.js` 副本
- `tests/seats.test.js`

## 现状

开台写入 `in_use_${seatId}`、维护写入 `maint_${seatId}`，均无 date/timeSlot；选座仅按 date+timeSlot 查询并过滤，导致体验中座位仍显示可约。

## 改动方案

1. `buildOccupancySets`：`in_use` / `maintenance` 且无时段字段时视为全局现场占用
2. `mergeOccupancyDocs`：合并时段占用与现场占用并按 `_id` 去重
3. 前端与确认云函数加载占用时一并拉取现场状态

## 风险

- 明日预约也会被当前体验中座位挡住（与「同步座位管理现场状态」一致，可接受）
- 需部署 `adminUpdateAppointment` 后后端拦截才生效

## 验证思路

- `node --test tests/seats.test.js`
- 断言无 date 的 in_use/maintenance 进入占用集合；reserved 仍按时段过滤
