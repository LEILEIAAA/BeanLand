# 计划：开台即写 seatIdsSnapshot，避免历史座位丢失

## 目标
测试环境复盘出现 `F1-A · —`：结束清空 `seatIds` 时若无快照则历史无座。开台写入 `seatIdsSnapshot`，结束时空 `seatIds` 不得覆盖已有快照。

## 范围
- `miniprogram/utils/seatSession.js`：`buildStartSessionRecord` / `buildEndSessionFields`
- 5 份云函数 `seatSession.js` 副本同步
- `tests/seatSession.test.js`

## 现状
- 结束才写 `seatIdsSnapshot`，同时 `seatIds: []`
- 快照上线前（或结束云函数未部署）已结的单 → 历史只有 `tableCode`

## 改动方案
1. 开台记录同时写入 `seatIdsSnapshot`（与 `seatIds` 同值）
2. 结束：有 live `seatIds` 则刷新快照；live 为空则保留已有 `seatIdsSnapshot`

## 风险
- 云函数副本漏同步 → 部署后仍不写开台快照；同步 5 份并提醒部署 `adminStartSeatSession` / `adminEndSeatSession`
