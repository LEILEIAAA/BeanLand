# 计划：停止计时后沉淀「本次记录」产物（店主复盘 + 会员查看）

## 目标
店主点「停止计时」结束会话后，产生可查看、可复盘的记录：
- 店主端：历史会话列表（复盘），含会员信息、座位、时段、时长、超时、消费金额。
- 会员端：我的到店记录，含座位、时段、时长、超时、消费金额。

## 现状
- `seat_sessions` 结束时（`adminEndSeatSession`）已写入 `status:'ended'`、`endedAt`、`totalMinutes`、`overtimeMinutes`，但把 `seatIds` 清空为 `[]`，且**无任何消费端**：
  - 店主端 `pages/admin/timer` 座位板只渲染 `status:'active'` 的 `board.sessions`，结束即消失。
  - 会员端 `records` 只有充值/消费流水，`works` 只有作品，无到店记录。
- 消费金额来源：店主「套餐核销并开台」时，`package-redeem` 页跳转 timer 时带 `packageOrderId`，但 timer `onLoad` **未解析**，链路断裂。套餐 `payAmountYuan` 即本次消费额。

## 改动方案
### 数据模型（seat_sessions 增字段）
- 开台时写入：`packageOrderId`、`packageName`、`consumedAmount`（元，= 核销套餐 payAmountYuan）。
- 结束时快照座位：`seatIdsSnapshot`（保留原 seatIds，供历史展示；不改动原 `seatIds:[]` 清空行为）。

### 后端
- `utils/seatSession.js`（含各云函数副本）：
  - `buildStartSessionRecord` 增 `packageOrderId/packageName/consumedAmount`。
  - `buildEndSessionFields` 增 `seatIdsSnapshot`。
- `adminStartSeatSession/index.js`：解析 `event.packageOrderId` → 读 `package_orders` → 把套餐名/消费额挂到对应会员的会话记录。
- 新增 `adminListSeatSessions`（店主，查 ended，按 endedAt 倒序）。
- 新增 `listMySeatSessions`（会员，按 memberOpenid 查，startedAt 倒序）。

### 前端
- 新增 `utils/seatSessionHistory.js`：纯展示映射（日期/时长/金额/座位）。
- `utils/api.js`：加 `adminListSeatSessions`、`listMySeatSessions`。
- `pages/admin/timer/index.js`：onLoad 解析 `packageOrderId`，startSession payload 带上。
- 新增页 `pages/admin/timer-history/`（店主复盘列表）。
- 新增页 `pages/member/seat-sessions/`（会员到店记录）。
- `utils/memberActions.js` + `pages/member/index.js`：加「到店记录」入口。
- `pages/admin/dashboard/`：加「计时复盘」入口。
- `app.json`：注册 2 个新页。

### 测试
- 新增 `tests/seatSessionHistory.test.js`。
- 更新 `tests/seatSession.test.js`（新字段）。
- 更新 `tests/memberActions.test.js`（新入口）。

## 风险
- 云函数 seatSession.js 有多份副本，需同步。
- ended 会话历史依赖新字段，历史旧数据无 `seatIdsSnapshot/consumedAmount`，展示需容错（缺失显示为空/0）。
- 会员端查询按 memberOpenid，内存排序避免索引依赖。
