## 实际改动

- `packagePurchase.js`：权益态（redeemed / 过期退）、默认 30 天、`packageSnapshot`、可核销/核销/过期退纯逻辑
- 履约：`purchasePackage` / `createPackageOrder` / `payPackageNotify` 写入 `expiresAt`、`validityDays`、支付拆分
- 云函数：`adminRedeemPackage`、`listMyPackageOrders`、`adminListMemberPackages`、`expirePackageOrders`
- C 端：会员「我的套餐」；店主看板「套餐核销」页路径为 `pages/admin/package-redeem`（避免与 TabBar `pages/packages` 撞名导致进不去）→ 核销并跳转座位开台
- 余额过期：列表懒结算原路退余额；微信过期：`expirePackageOrders` 调云支付退款，失败挂 `expired_refund_pending`

## 关键决策

- 权益载体用 `package_orders`，不另开通行证表
- 历史无 `expiresAt` 的 `fulfilled` 单：可核销、不自动过期退
- 核销与开台解耦：核销成功即 `redeemed`，开台失败不回滚

## 残留风险

- 需部署新云函数；`expirePackageOrders` 建议在云开发控制台配每日定时触发
- 微信退款依赖 `cloud.cloudPay.refund` 与商户号配置；失败单需重试或人工处理
- 真机联调前会员入口/店主核销需云函数上线
