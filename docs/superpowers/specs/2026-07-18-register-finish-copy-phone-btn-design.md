# 注册页完成提示与手机号按钮

日期：2026-07-18

## 背景

注册页底部「已完成 x/3」与按钮「请完成以上三项」在部分完成时语义打架；已授权后「更换微信手机号」仍用大黑主按钮，抢底栏主 CTA。

## 目标

1. 未完成时底栏按钮按缺口提示，与进度同源。
2. 手机号：未授权主按钮，已授权弱链接（对齐昵称更换）。
3. 完成判定逻辑不变。

## 非目标

- 不改 `isRegistrationComplete` / 拦截门禁规则
- 不改设置页手机号交互

## 完成判定（不变）

三项全部满足才算注册完成：

1. 头像：已选用（非默认豆图）
2. 昵称：已选用（非空，且非 `Bean artist*` 系统默认名）
3. 手机号：合法 11 位大陆号

进度 `doneCount` 与按钮文案均由同一三项布尔值推导。

## 底栏文案

| 状态 | 提示文案（按钮上方） | 按钮 |
|------|----------------------|------|
| 0～2 项完成 | `还需完善：{缺口列表}` | `确认注册`（disabled） |
| 3 项完成 | `已完成 3/3` | `确认注册` |

## 微信昵称

- 仅允许微信昵称填充（`type="nickname"`），逐字手输会被清空并提示
- UI 表现为授权按钮，透明命中层触发系统昵称能力（微信无此入口）

## 手机号区块

| `hasPhone` | 控件 |
|------------|------|
| false | 黑底主按钮：`授权微信手机号`（现有 `btn-phone-auth`） |
| true | 展示脱敏号 + 弱链接文案 `更换微信手机号`（样式对齐昵称 `nickname-sync-label`），仍为 `open-type="getPhoneNumber"` |

## 实现要点

- 在注册页（或 `memberProfile` 若可测）导出/计算 `missingLabels` / `finishButtonText`
- WXML：手机号按钮按 `hasPhone` 切换 class（主按钮 / 弱链接）
- 测试：缺口文案拼接、三项齐时按钮文案

## 验收

1. 任意缺口组合下，进度与按钮文案一致且只列未完成项。
2. 三项齐后按钮为「完成注册并返回」且可返回。
3. 未授权手机号为大按钮；已授权为弱链接，不抢底栏主色。
